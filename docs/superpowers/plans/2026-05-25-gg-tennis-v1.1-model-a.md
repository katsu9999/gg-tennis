# GG Tennis Shuffle v1.1 — Model A (Host-of-the-Day + Club PIN)

**Date:** 2026-05-25
**Branch:** `feat/host-of-the-day-model`
**Spec basis:** `docs/superpowers/specs/2026-05-25-gg-tennis-shuffle-design.md`

## 1. Goal

Replace the persistent admin allowlist + magic-link model with:

- **No persistent admin role.** The person who starts today's session is the host *for that session only*.
- **Open operation after start.** Once a session is `ongoing`, anyone can record winners, advance rounds, and end the session (Realtime sync keeps everyone in sync).
- **Club PIN for destructive ops only.** Member delete / venue edit / planned-session create / GDPR export require a shared club PIN.
- **No login flow.** Visitors open the URL and can immediately start playing or spectate.

## 2. Why Model A + A3

- Admin allowlist tends to grow until "everyone is admin", defeating the purpose.
- Magic-link friction is overkill for a small trusted club.
- Real-time visibility (who tapped what) + Undo replaces the need for one-operator-per-session.
- Destructive ops are rare and well-guarded by a shared secret + audit log.

## 3. Permission matrix (target state)

| Operation | Who | Mechanism |
|---|---|---|
| Read everything | Anyone with URL | RLS `select using (true)` |
| Start session | Anyone | `sessions` anon INSERT |
| Operate session (rounds, winners, end) | Anyone, while session `ongoing` | `sessions`/`match_log`/`pair_history` anon write |
| Delete member | PIN holder | RPC `delete_member(pin, id)` |
| Add/edit member | PIN holder | RPC `upsert_member(pin, ...)` |
| Add/edit venue | PIN holder | RPC `upsert_venue(pin, ...)` |
| Create planned session | PIN holder | RPC `upsert_planned_session(pin, ...)` |
| Rotate RSVP token | PIN holder | RPC `rotate_public_rsvp_token(pin, id)` |
| Edit settings (PIN itself etc.) | PIN holder | RPC `update_settings(pin, ...)` |
| RSVP self-edit | Public link visitor | Existing RLS (unchanged) |

## 4. Data model changes

### 4.1 `sessions` — host label
```sql
alter table sessions add column if not exists host_token text;
alter table sessions add column if not exists host_label text;  -- nullable display name
```

### 4.2 `settings` — club PIN
```sql
alter table settings add column if not exists club_pin_hash text;
-- bcrypt hash. nullable; if null, PIN gating is OFF (dev convenience).
```

### 4.3 `operation_log` — audit trail (new table)
```sql
create table if not exists operation_log (
  id          bigserial primary key,
  occurred_at timestamptz not null default now(),
  actor_token text,           -- LocalStorage token (anonymous, just to attribute)
  actor_label text,           -- display name supplied client-side
  op          text not null,  -- 'start_session', 'tap_winner', 'delete_member', etc.
  target_kind text,
  target_id   text,
  payload     jsonb not null default '{}'
);
create index operation_log_occurred_at_idx on operation_log(occurred_at desc);
```

## 5. RLS rewrite

### 5.1 Open up session operation tables
```sql
-- sessions, match_log, pair_history: anon write (insert/update) allowed.
-- Reads already public.
drop policy if exists "admin write sessions"      on sessions;
drop policy if exists "admin write match_log"     on match_log;
drop policy if exists "admin write pair_history"  on pair_history;

create policy "anon insert sessions"
  on sessions for insert to anon with check (status = 'ongoing');

create policy "anon update sessions"
  on sessions for update to anon
  using (true) with check (status in ('ongoing', 'past'));

create policy "anon insert match_log"
  on match_log for insert to anon with check (true);

create policy "anon write pair_history"
  on pair_history for all to anon
  using (true) with check (true);
```

### 5.2 Lock down PIN-gated tables (no direct write at all)
```sql
-- members, venues, planned_sessions, admins, settings: drop admin-only policy.
-- All writes must go through SECURITY DEFINER RPC functions.
drop policy if exists "admin write members"          on members;
drop policy if exists "admin write venues"           on venues;
drop policy if exists "admin write planned_sessions" on planned_sessions;
drop policy if exists "admin write admins"           on admins;
drop policy if exists "admin write settings"         on settings;
drop policy if exists "admin write rsvps (any)"      on rsvps;
-- No replacement insert/update/delete policies for anon. RPC functions bypass RLS via SECURITY DEFINER.
```

### 5.3 Operation log
```sql
alter table operation_log enable row level security;
create policy "read operation_log anon" on operation_log for select using (true);
create policy "anon insert operation_log" on operation_log for insert to anon with check (true);
-- No update or delete. Immutable audit trail.
```

## 6. RPC functions (PIN-gated, SECURITY DEFINER)

```sql
create or replace function verify_club_pin(pin_input text) returns boolean
language plpgsql stable as $$
declare
  stored_hash text;
begin
  select club_pin_hash into stored_hash from settings where id = 1;
  -- Null hash = PIN gating disabled (dev only).
  if stored_hash is null then
    return true;
  end if;
  return crypt(pin_input, stored_hash) = stored_hash;
end;
$$;
-- Requires pgcrypto extension. Enable in migration 0004.

-- Members
create or replace function upsert_member(p_pin text, p_id bigint, p_name text, p_status text)
returns bigint
language plpgsql security definer set search_path = public as $$
declare
  v_id bigint;
begin
  if not verify_club_pin(p_pin) then raise exception 'invalid_pin'; end if;
  if p_id is null then
    insert into members(name, status) values (p_name, p_status) returning id into v_id;
  else
    update members set name = p_name, status = p_status where id = p_id returning id into v_id;
  end if;
  return v_id;
end;
$$;

create or replace function delete_member(p_pin text, p_id bigint) returns void
language plpgsql security definer set search_path = public as $$
begin
  if not verify_club_pin(p_pin) then raise exception 'invalid_pin'; end if;
  delete from members where id = p_id;
end;
$$;

-- Venues, planned_sessions, settings: similar pattern.
-- See migration file for full list.
```

Granted to anon:
```sql
grant execute on function verify_club_pin(text) to anon;
grant execute on function upsert_member(text, bigint, text, text) to anon;
grant execute on function delete_member(text, bigint) to anon;
-- etc.
```

## 10. Migration sequence

For an existing v1 deployment:
1. Apply `0004_v1_1_schema.sql` (add columns + operation_log + pgcrypto).
2. Apply `0005_v1_1_rpc.sql` (RPC functions + grants).
3. Apply `0006_v1_1_rls.sql` (RLS policy rewrites).
4. Operator runs: `update settings set club_pin_hash = crypt('1234', gen_salt('bf'));` (or via UI after first deploy).
5. Deploy v1.1 frontend.
6. (Optional) `truncate admins;` — admin allowlist no longer used.
