# シャッフル公平性改善 計画書 (2026-07-12)

## 背景 (Katsuの要望)
- **6人のとき**: シャッフルが物足りない。シングルスばかりになる。みんなシングルスは嫌なので、なるべくダブルスに当たるようにしたい。
- **シングルス**: やる場合も順繰りに公平に当たるようにしたい（同じ人が連続でシングルスにならない）。
- **13〜14人**: 休憩ローテーションはランダムより層当たり（公平）を維持したい。→ 調査の結果すでに理論最適なので変更なし。

## 調査で判明した根本原因
1. `planRound` が v1.1 で「コート最大利用」方針に変更され、6人3面 → 全員シングルス化。
2. `buildRound` はシャッフル列の末尾をシングルスに機械的に流し込むだけで、**シングルス回数を追跡・公平化する仕組みが皆無**。連続シングルス発生率ほぼ100%。

## 設計

### Fix ① planRound を「ダブルス優先」に変更
方針: **休憩者最小 → シングルスコート最小（ダブルス最大化）** の優先順位。
- `seated = min(N, 4*courts)` を偶数に丸める（余った1人は休憩）。
- `doublesCourts = floor(seated/4)`、`singlesCourts = (seated - 4*doublesCourts)/2`。
- `allowSingles=false` の挙動は不変。
- トレードオフ: 予約コートが空くことがある（例 8人3面 → 2D、1面空き）。Katsuの明示的な要望（シングルス回避）を優先。

### Fix ② シングルス公平化
- `todayStats` に `singles` カウントを追加（`{ play, rest, singles }`）。
- `buildRound` に `singlesCount` マップと `prevSingles` セットを渡し、シングルスコートに配置された選手へ
  ペナルティを加算（累積回数 × 大きい重み + 前ラウンドもシングルスなら追加）。
- 800回探索がペア多様性を保ちつつ、シングルス回数の少ない人を自然にシングルスへ回す。
- `prevSingles` は `prevResters` と同様、直近ラウンドから導出（resume時も復元）。永続化は `todayStats` 経由。
- キーは `JSON.stringify(ref)`（ゲストも公平対象に含まれる）。
